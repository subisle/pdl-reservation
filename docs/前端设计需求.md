# 胖东来预约抢购 —— 前端设计需求文档

> 版本 1.0 · 2026-10-02 · 基于现有 `pdl_grab/webui.html` + `pdl_grab/web.py` 接口逆向整理

---

## 1. 项目背景

胖东来门店预约抢购工具目前提供一个本地 Web UI（`http://127.0.0.1:8765`），用于配置预约目标、选择场次、管理多账号、发起抢购并实时查看日志。本需求文档定义该 Web UI 的完整前端设计规范，作为后续重构或换框架（React/Vue）的实施依据。

### 1.1 目标

- 让用户在 3 步内完成「选店 → 选场次 → 开始抢购」完整链路。
- 多账号抢购时实时反馈每个账号的独立状态，不混淆日志。
- 移动端可操作（主要在桌面浏览器使用）。
- 无后端改造的前提下保持现有 REST + SSE 接口兼容。

### 1.2 用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 主用户 | 本人操作，单设备 | 快速选店选场次，一键抢购，实时看日志 |
| 多账号用户 | 代刷/家人帮抢 | 批量录入账号，分组查看结果 |

## 2. 页面结构

SPA 单页，顶部 tab 导航，共 5 页：

```
┌──────────────────────────────────────────┐
│  [抢购]  [目标]  [场次]  [账号]  [日志]    │
├──────────────────────────────────────────┤
│                                          │
│              <当前页面内容>               │
│                                          │
└──────────────────────────────────────────┘
```

### 2.1 抢购页（`p-grab`）—— 默认首页

| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 状态条 | 当前目标门店/品类/场次、token 状态（绿/灰）、MQTT 状态 | `POST /api/config` |
| 抢购参数 | warmup_seconds / max_publish / result_timeout | `POST /api/config` |
| 主按钮 | 「开始抢购」/「停止」 | `POST /api` action=`grab` / `stop` |
| 预检按钮 | 「预检」 | `POST /api` action=`preflight` |
| 结果面板 | 最近一次结果（成功/失败 + 每账号状态） | `POST /api` 返回 |

**交互**

- 「开始抢购」点击后变「停止」按钮（红色）。
- 结果面板在抢购进行中显示 spinner + "等待 MQTT 响应…"。
- 预检结果以格式化字段渲染，不用原始 JSON。

### 2.2 预约目标页（`p-target`）

| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 城市选择 | 下拉框，选项来自内置城市列表 | `pdl_grab/regions.py` |
| 加载门店 | 按钮，点击后列出附近门店 | `POST /api` action=`catalog` |
| 门店列表 | 表格：许昌市 / 胖东来时代广场(1007) / 胖东来天使城(1012) / 胖东来大胖店(1009) / 胖东来二胖店(1010) / 胖东来三胖店(1011)，每行含距离和可约品类 | `catalog` 返回 |
| 品类选择 | 门店行内 radio：超市(04) / 茶叶(03) / 医药(05) | 同上 |
| 加载业态 | 按钮，点击后展开业态/分类/专柜 | `POST /api` action=`stru` |
| 保存配置 | 按钮 | `POST /api` action=`config` |

**交互**

- 选择门店后自动填入 `store_code`、`business_code`。
- 「加载业态」显示 loading 状态，失败时行内红字提示。
- 经纬度可手动输入或点击「自动定位」。

### 2.3 场次页（`p-sessions`）

| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 加载场次 | 按钮 | `POST /api` action=`sessions` |
| 场次列表 | 表格：场次编码 / 名称 / 日期 / 开始时间 / 状态 | `sessions` 返回 |
| 选中标记 | 当前 `session_code` 行高亮 | 状态 |

**状态列渲染**

| 值 | 含义 | 显示 |
|----|------|------|
| `0` | 未开始 | 灰色「未开始」 |
| `1` | 可约 | 绿色「可约」 |
| `2` | 已约满 | 红色「已满」 |
| 其他 | — | 黄色原始值 |

**交互**

- 点击行 → 弹出确认 → 设置 `session_code` → 跳转抢购页。
- 空列表显示"当前无场次"空状态。

### 2.4 账号页（`p-accounts`）

| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 批量导入 | textarea，每行一条 `名称,token` | `POST /api` action=`accounts` |
| 账号列表 | 表格：名称 / token（打码）/ 专属场次（可选） | 同上 |
| 删除 | 每行操作 | 同上 |

**交互**

- token 显示前 4 后 4 位 + `****`。
- 添加/删除后立即刷新列表。
- 至少保留一个账号（防止误删全部）。

### 2.5 日志页（`p-log`）

| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 实时日志 | 等宽字体、自动滚动到底部 | `GET /api/events` (SSE) |
| 清屏 | 按钮 | 前端本地清空 |

**交互**

- SSE 断开自动重连（3s 间隔）。
- 日志按时间戳着色：错误红 / 成功绿 / 普通灰。
- 最大显示 500 条（对齐后端 `deque(maxlen=500)`）。

## 3. 全局组件

| 组件 | 说明 |
|------|------|
| Tab 栏 | 顶部 sticky，移动端可横向滚动 |
| Toast | 右上角弹出，2.5s 自动消失 |
| Modal | 确认操作（选场次、删除账号） |
| Spinner | 按钮内 loading 动画（CSS animation） |
| Empty State | 各列表为空时显示图标 + 提示文字 |

## 4. 通信层

### 4.1 REST

所有业务请求 `POST /api`，Body 格式：

```json
{ "action": "sessions", "data": { "storeCode": "1007", "businessCode": "03" } }
```

返回：

```json
{ "ok": true, "data": { ... } }
```

### 4.2 SSE

`GET /api/events` → `text/event-stream`，每条消息为一个 log string。

### 4.3 错误处理

| HTTP 状态 | 前端行为 |
|-----------|----------|
| 200 | 按 `ok` 字段判断，`ok=false` 时 Toast 显示 `data.msg` |
| 4xx/5xx | Toast 显示通用错误 |
| 网络失败 | Toast "网络异常，请确认服务在运行" |

## 5. 状态管理

前端不需要独立状态管理库，用全局对象：

```js
const state = {
  tab: 'grab',
  cfg: { token:'', store_code:'', business_code:'', session_code:'', ... },
  sessions: [],
  accounts: [],
  logs: [],
  busy: false,
};
```

每次页面切换时从 `/api/config` 拉取最新配置填充。

| 断点 | 布局 |
|------|------|
| ≥768px | 标准 5 列 tab |

## 8. 验收标准

1. 启动 `python -m pdl_grab.cli web`，浏览器打开后默认进入抢购页。
2. 目标页选择城市 → 加载门店 → 选门店+品类 → 保存，`config.json` 对应字段更新。
3. 场次页加载后能正确区分"可约"和"已满"状态。
4. 点击"开始抢购"后日志页实时收到 SSE 消息。
5. 多账号抢购时结果面板按账号分组展示。
6. 所有列表有空状态，所有按钮有 loading/禁用态。
7. 1440px 和 375px 宽度下均不出现横向溢出（表格允许滑动）。
